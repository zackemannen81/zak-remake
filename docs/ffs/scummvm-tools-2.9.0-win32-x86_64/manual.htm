1. What is SCUMM

SCUMM is a programming language for point'n'click style games developed in 1987 by Aric Wilmunder and Ron Gilbert of LucasArts Entertainment Company (it means Script Creation Utility for Maniac Mansion). If you have never seen one of these wonderful games that uses SCUMM, then you won't understand what this program is about, so go out and try a LEC game first.

SCUMM is also an encoding language because it manages various file types like images, sounds, animations, musics, scripts...

There are many different versions of SCUMM. The fundamental differences are in the datatypes contained into files, but there are also encryption differences and other things.
We can identify various SCUMM branches on the Mac:


  • version 1 (Maniac Mansion)
  • version 3 (Indiana Jones and the Last Crusade, Loom)
  • version 5 (Monkey Island 1&2, Indiana Jones and the Fate of Atlantis)
  • version 6 (Sam&Max Hit the Road, Day of the Tentacle)
  • version 7 (Full Throttle, The Dig)


The last two versions showed a slight variation in the data files, where all the game files were joined together into one huge datafile, while the last version is similar to the previous but its datafiles are no more encrypted and they contain video streams and high quality audio samples.

If you want to know more about SCUMM blocks supported by SCUMM Explorer, read the section entitled More info on SCUMM blocks.


2. What is SCUMM Explorer

SCUMM Explorer is the first (and only!) program available on Macintosh for viewing SCUMM files from LucasArts Entertainment Company games. When you load a datafile you will be presented a list of all the data in that file divided into blocks. Each block represents an object of the game (an image, a sound, ...) and you can view each block content or export its data (depending on the block type) on disk or also convert it in a different - universal - format. That is, you can discover the "backstage" of the game, its structure and more than you had ever known about it.


3. Features in SCUMM Explorer

Once you load one or more SCUMM files you will be able to do the following (depending on the version of the game):


  • Surfing through its blocks from a hierarchical list
  • Dump a block in hex or ascii (up to 32 MBytes of data) or save its data to a new, separated file
  • Display the Color LookUp Table (palette) of a certain Room, Actor Costume or Animation Frame and export it to a file containing a Mac 'clut' resource
  • View a background image from a Room block or save it to a picture file, or to a different file type (using Quicktime)
  • View an Object image from a Room block or export one of its frames to a picture file, or to a different file type (using Quicktime)
  • Play sounds in sound blocks of Monkey Island 1 and save them to System 7 sound files
  • Play music tracks and export them to General Midi files or QuickTime Music files
  • Decompile game scripts (using DeScumm from the ScummVM project) and save them to text files


What you cannot do:

  • Costume (characters animations) viewing
  • Video playing
  • Listening of sound and music from later games
  • Viewing of walkable areas, boxes and other room amenities
  • editing
  • everything else here uncovered

8. More info on SCUMM blocks


SCUMM data for newest games is organized into LFLF blocks, whose purpose is the same as that of the "<number>.LFL" files used in old SCUMM games. Each LFLF block (or each xx.LFL file for old games) contains a ROOM sub-block that owns other sub-blocks describing an entire piece of the game, including images, objects, palettes, walking boxes and scripts.
A palette block ("CLUT") is a group of colors, usually 256 - it can be viewed or exported to the standard Mac 'clut' format.
A room image block contains a background image which can be viewed and exported to the standard Mac picture format or to a different image format. It is named "RMIM" (or simply Room for the old games).
An object image block ("OBIM") contains all the frames that makes up an animated object. Each single frame can be viewed and exported too.
A script block inside a ROOM usually describes objects behaviour ("OBCD" blocks), a room entering or exiting code ("ENCD" or "EXCD") or a local function ("LSCR"). Scripts can be disassembled using DeSCUMM, a tool from ScummVM which is included in SCUMM Explorer.


Outside the ROOM block there may be other blocks, such as sounds, scripts and costumes.
Sound blocks contains musics or sound samples, so if you select them you'll be able to listen to the music/sound. The sound blocks are usually found under the LFLF blocks. They're named "SOUN" or "SOU". The musical sound blocks (that you can listen to) are named "MAC", "SPK", "ADL", "ROL", "GMD ", "MIDI" for most games and "Mac0" for Monkey Island 1. The sound samples blocks supported are named "Mac1", they can be found in Monkey Island 1. Sound effects can also be found (for talkie games) in a file named "monster.sou", into blocks named "Crea" that stands for Creative Sound File (though those are not supported by SCUMM Explorer).
Last but not least, script blocks are also located outside ROOM blocks, directly in the LFLF blocks as global scripts ("SCRP" blocks). Again, these can be viewed using DeSCUMM.
Costumes ("COST" blocks) are the images of characters animations. They're not supported by SCUMM Explorer.

That's all you need to know to use this program in its current release, but keep reading if you want to know more on SCUMM blocks.



The SCUMM blocks

Here is a brief description of the most important SCUMM blocks:

  • LECF: the main block containing the entire file.
  • LOFF: the offsets to identify the LFLF blocks position.
  • LFLF: the blocks which made up most LEC files.

The following blocks are found into the LFLF blocks:
  • ROOM: a parent block containing all of the info blocks for a specific part of the game.
  • SCRP: a script block containing the game's code in SCUMM programming language.
  • SOUN: a sound block which contains one or more sound effects or tunes.
  • COST: a costume block with all the images that makes up a character's animation sequence.

Those are the main blocks which compose a room:
  • RMHD: the room header.
  • BOXD: the desciption of the walking boxes (the areas where characters may walk on).
  • BOXM: the walking box matrix.
  • CLUT: the color lookup table.
  • PALS: another format of color lookup table.
  • SCAL: the perspective scaling informations for the walking characters.
  • RMIM: the room's image.
  • OBIM: an object's image.
  • OBCD: an object's code.
  • EXCD: the code executed upon exiting the room.
  • ENCD: the code executed upon entering the room.
  • NLSC: the local scripts count
  • LSCR: scripts in SCUMM programming language related to the room.

These blocks can be found into a sound block:
  • GMD : general Midi music.
  • MIDI: general Midi (again).
  • MAC : Mac Midi music.
  • ROL : Roland MT-32 Midi music.
  • ADL : Ad-Lib Midi music.
  • SPK : PC speaker Midi sequence.
  • Mac0: Monkey Island 1 music
  • Mac1: Mac formatted Sound
  • SBL : Sound Blaster sound effect


    Well, you'll probably find other block types in a game, but this list should give you an idea of how the SCUMM files are organized.
